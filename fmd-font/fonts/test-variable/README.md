# FmdTestVF — project-authored OFL variable-font fixture

`FmdTestVF.ttf` is a **tiny synthetic OpenType variable font** authored in this
repository for parser tests (`gk3v.1`). It is not a design face.

## Provenance

- **Author:** franken_markdown test fixture, generated by the deterministic
  sfnt builder in `fmd-font/src/lib.rs` (`synthetic_font_tests::fmd_test_vf_bytes`).
- **License:** SIL Open Font License 1.1 (see `OFL.txt`). No Reserved Font Name.
- **Why it exists:** `Font::parse` requires a complete sfnt (`head`/`maxp`/
  `hhea`/`hmtx`/`cmap`) even when the test target is `fvar`/`avar`. Vendoring a
  multi-megabyte retail VF would dwarf the crate; this fixture is a few hundred
  bytes and encodes exactly the tables the tests assert.

## Contents

| Table | Role |
| --- | --- |
| `head` / `maxp` / `hhea` / `hmtx` / `cmap` | Minimum parseable static skeleton (1 glyph) |
| `fvar` | One `wght` axis, user space 100 / 400 / 900, two named instances (Regular=400, Bold=700) with PostScript name IDs |
| `avar` | Identity map `(-1,-1), (0,0), (1,1)` |

`FmdTestVF.ttf` has **no** `glyf`/`gvar`. Outline instancing, mixed-weight PDF,
and cmap-shared bbox L∞ comparisons use `fmd_font::variable_triangle_fixture()`
(built in `fmd-font/src/gvar.rs`). Dump it for CLI e2e with:

```bash
FMD_DUMP_TRIANGLE_VF=/tmp/FmdTriangleVF.ttf cargo test -p fmd-font dump_triangle_vf_when_requested -- --exact
```

The method and size report live in [`docs/VARIABLE_FONTS.md`](../../../docs/VARIABLE_FONTS.md).

Regenerate (does not overwrite this directory; copies from `/tmp`):

```bash
FMD_DUMP_TEST_VF=1 cargo test -p fmd-font fmd_test_vf_fixture_round_trip -- --exact
cp /tmp/FmdTestVF.ttf fmd-font/fonts/test-variable/FmdTestVF.ttf
```

## Independent packed-delta fixture

`FmdPackedDeltasVF.ttf` is a 1,660-byte original test font, released under the
same OFL 1.1 license and copyright as `FmdTestVF.ttf`. It contains an empty
`.notdef`, a triangle at `A`, and one `wght` variation. The variation mixes
zero runs, signed byte runs, signed word runs, X/Y deltas, and a right-phantom
advance adjustment. Unlike the in-crate synthetic builders, FontTools encodes
its complete `glyf`/`gvar` tables independently. This catches an incorrect
packed-delta interpretation even if a handwritten fixture repeats that error.

The integration regression checks every triangle vertex and both horizontal
metrics at weights 400, 650, and 900 against the FontTools instancer. Regenerate
and verify with FontTools 4.61.1:

```bash
python fmd-font/fonts/test-variable/generate_packed_deltas.py
```

FontTools is only needed to regenerate the fixture; normal Rust tests read the
committed font without Python or third-party font libraries.

## Independent composite-variation fixture

`FmdCompositeVariationsVF.ttf` is a 1,964-byte original OFL test font generated
by FontTools 4.61.1. Its composites come before their children in glyph order.
The face includes independently varied bases and accents, component placement
deltas, horizontal phantom-point deltas, byte offsets that must become word
offsets, a scaled nested parent without its own variation tuple, and an accent
attached to a parent outline point.

`generate_composite_variations.py` produces the font and
`FmdCompositeVariationsVF.json`. The JSON records every outline vertex, glyph
bounding box and horizontal metric from independently instanced, saved and
reparsed FontTools static fonts at weights 400, 650 and 900. Saving first makes
the oracle include the integer-coordinate rounding of an actual TrueType font.

`tests/composite_variation_test.rs` checks those coordinates and metrics, strict
subset preservation, final checksums, immutable source bytes, deterministic
instances, composite-cycle refusal and the OpenType last-`USE_MY_METRICS` rule.
The original handwritten component fixtures now use the standard ordering:
component pseudo-points first, followed by four phantom points. Regenerate with:

```bash
python fmd-font/fonts/test-variable/generate_composite_variations.py
```

## Independent horizontal and face-wide variation metrics

`FmdMetricsVF.ttf` (2,296 bytes) and `FmdMappedMetricsVF.ttf` (2,340 bytes)
are original OFL fixtures generated by FontTools 4.61.1. Each contains four
glyphs, including an empty space, a `wght` axis with a nonlinear `avar` map,
and a `wdth` axis held at its default. Negative, positive and intermediate
regions vary glyph advances, side bearings and face-wide metrics. Their
`gvar` phantom deltas and `HVAR` deltas agree, so instancing must apply the
metric change only once.

The first font uses implicit HVAR advance indices. The second uses two item
variation subtables and packed advance/left/right-bearing maps, including a
map shortened by sharing its final entry. Both fonts exercise MVAR fields in
`OS/2`, `hhea`, `vhea`, `post` and `gasp`. No third-party font outlines or
variation data are copied.

`generate_metric_variations.py` instantiates and serializes these fonts with
FontTools at weights 100, 250, 400, 525, 650 and 900. The committed
`metric-variations-reference.tsv` records the reparsed horizontal metrics,
face metrics, global outline bounds and horizontal-header summaries. Normal
Rust tests read the font bytes and reference values without Python or
FontTools. Regenerate with:

```bash
python fmd-font/fonts/test-variable/generate_metric_variations.py
```

The oracle has one explicit limitation: FontTools 4.61.1 does not implement
MVAR `gsp0` through `gsp9`. Those fields are excluded from its TSV rather than
treated as unchanged expected values. The Rust integration test checks
`gsp0`/`gsp1` against separate, explicit expectations from the
[OpenType MVAR specification](https://learn.microsoft.com/en-us/typography/opentype/spec/mvar),
including interpolation after `avar`, upward half-unit rounding and the
unchanged terminal `0xFFFF` range.

`tests/variation_metrics_test.rs` also checks empty-glyph metrics with and
without HVAR, deterministic instances and immutable input bytes, preservation
through strict subsetting, overflow refusal, table extents and malformed
indices, plus prefix truncations and seeded mutations of both metric tables.
The item-variation reader's unit tests cover multiple axes, mixed signed
delta widths, null subtables, packed map sizes, the no-variation sentinel,
shared-row caching and aggregate work/storage bounds.
